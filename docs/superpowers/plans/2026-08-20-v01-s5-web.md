# Plimsoll v0.1 Slice 5 — Web

**Delivered:** the half of the v0.1 journey a user repeats — sign in, see the
runs, open one and watch it.

Not a plan written before the work: this records what was built and, more
usefully, what was not, so the next person starts from the truth rather than
from the roadmap's ticks.

## What is there

```
apps/web/src/app/page.tsx          Sign-in, then the run list
apps/web/src/app/runs/[runId]/     One run, in four cards
apps/web/src/lib/api.ts            Where a request is shaped and a token attached
apps/web/src/lib/types.ts          The shapes this interface reads
apps/web/src/lib/useLiveRun.ts     The run's WebSocket
```

A run's page shows its status and the commit and bundle digest it is pinned to;
live windows while it runs; the merged per-transaction percentiles; the SLA
verdict per rule with the value each measured; and failures grouped by
fingerprint with a count and one verbatim example.

## Decisions worth keeping

- **The browser reaches the API directly**, not through a Next.js proxy. One
  origin to reason about, one place the token lives, and no server-side copy of
  a credential belonging to the person holding the tab. CORS is therefore
  load-bearing, and `PLIMSOLL_CORS_ORIGINS` lists origins rather than opening
  them — this API is reached with a bearer token, and a permissive origin would
  let any page a user visits spend it.
- **Live windows are keyed and replaced, never accumulated.** Each announcement
  carries that window's running total, because a window can be announced more
  than once. Accumulating would double-count and the dashboard would disagree
  with `GET /runs/{id}/metrics`.
- **Status never travels by colour alone.** The label is always rendered, so the
  meaning survives a monochrome screen, a printed report, and anyone who does
  not distinguish red from green.
- **`src/lib/types.ts` is hand-written and narrow**, covering only the fields the
  pages use, so a contract change breaks a build rather than a page at run time.
  The generated types in `@plimsoll/contracts` remain the contract of record.

## What is not there

- **Creating anything.** Projects, script repositories, and tests are API-only.
  A first-time user cannot get from nothing to a run without the terminal, which
  is the largest gap between this and a shippable v0.1.
- **Pools, credentials, and target policy** have no screens; they are operator
  configuration and are set over the API.
- **No charts.** The live and results views are tables. A time-series chart of
  throughput and latency is the obvious next thing and wants
  `docs/architecture/03-metrics-pipeline.md` read first, because the numbers it
  would draw must come from merged sketches and never from averaged percentiles.
- **No end-to-end browser suite.** The journey was driven manually through a
  real browser and verified from the rendered page; `make e2e` in the README is
  still aspirational.
